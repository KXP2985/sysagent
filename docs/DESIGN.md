# SysAgent 设计与可行性分析

> 目标：一个可部署在 Windows / Linux 上的智能体，能感知系统状态、按指令分析状态、
> 实时监听项目日志并在出问题时上报 + 给出解决方案；进阶能力为受限的电脑控制。

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                  Web 控制台 (浏览器)                      │
│  概览 │ 对话 │ 日志 │ 告警 │ 记忆与能力 │ 设置            │
└──────────────┬──────────────────────────▲───────────────┘
               │ HTTP / WebSocket          │ 推送(状态/日志/告警/提案)
┌──────────────▼──────────────────────────┴───────────────┐
│                  FastAPI 服务端 (agentd)                 │
│  ┌────────────┐  ┌────────────┐  ┌────────────────────┐ │
│  │ 系统状态采集 │  │ 日志监听器  │  │ Agent 工具循环      │ │
│  │  (psutil)   │  │ (tail+规则) │  │ (LLM+工具调用)      │ │
│  └────────────┘  └─────┬──────┘  └─────────┬──────────┘ │
│                        │ 命中错误规则        │ 工具执行    │
│  ┌──────────────┐  ┌───▼───────────────────▼──────────┐ │
│  │ 长期记忆      │  │ 白名单 + 审批 + 能力进化提案        │ │
│  │ fact/lesson/  │  │ (runtime overlay 热加载)          │ │
│  │ playbook      │  └────────────────────────────────┘ │
│  └──────┬───────┘                                      │
└─────────┼──────────────────────────────────────────────┘
          │ 记忆摘要注入提示词              │
   ┌──────▼──────┐  ┌──────────────┐ ┌─────▼──────┐
   │ 被监控项目    │  │ LLM Provider │ │ data/      │
   │ 日志/进程     │  │ OpenAI兼容 /  │ │ memory.jsonl│

                                     └────────────┘

技术栈：Python 3.10+ / FastAPI / psutil / httpx / 原生 HTML+JS 前端（无构建步骤）。

## 2. 可行性分析（实事求是）

### 2.1 基础功能——可行度高

| 能力 | 实现方式 | 可行性 | 已知限制 |
|------|---------|--------|---------|
| 系统状态感知 | psutil 采集 CPU/内存/磁盘/网络/进程 | ✅ 成熟可靠，跨平台一致 | 容器内可见信息受限；个别指标 Win/Linux 命名不同（已做归一） |
| 日志实时监听 | 轮询 tail（0.5s），支持日志轮转/切割 | ✅ 可靠，轮转场景已处理 | 超大文件只读增量，不回读全量；网络文件系统延迟略高 |
| 问题及时上报 | 两层检测：① 规则层（ERROR/Traceback 等正则）② LLM 层（语义分析） | ✅ 规则层零延迟零成本，LLM 层补充语义 | 规则层依赖日志规范程度；LLM 层有 2–10s 延迟、按 token 计费 |
| 协助给出解决方案 | 把出错上下文 + 系统状态喂给 LLM，工具调用取证（翻日志、查进程）后再回答 | ✅ 这正是 LLM 擅长的 | **不能保证方案 100% 正确**，本质是"辅助建议"，落地执行仍需白名单/人工审批兜底 |
| 按指令分析状态 | Agent 工具循环：LLM 自主调用 get_status / read_log / list_processes 等工具 | ✅ 主流 Function Calling 均支持 | 依赖所选模型的工具调用能力；弱模型可能多轮才收敛 |

### 2.2 进阶功能——控制电脑、记忆与自我进化

| 方案 | 可行性 | 风险 | 本项目决策 |
|------|--------|------|-----------|
| 白名单命令执行（启停进程、执行预定义命令、读写指定目录） | ✅ 完全可行 | 低：范围可控 | **第一版采用**；额外要求：危险操作 Web 端人工审批 |
| 鼠标键盘控制、改注册表/系统设置、任意文件删除 | ⚠️ 技术上可行（pyautogui 等） | 高：误操作代价大、权限难收敛 | **暂不纳入**，作为二期，需先做好审计日志与权限隔离 |
| 全自主执行（无审批） | ❌ 不建议 | 极高 | 永远保留审批兜底，与"实事求是"一致 |
| 长期记忆（事实/经验/剧本） | ✅ JSONL + 关键词/中文二元组检索即可 | 低：条目可审计可删除 | **已实现**；每次回答自动注入相关记忆摘要 |
| 自我进化（提案新命令/新监听/新剧本） | ✅ 提案制 + runtime overlay 热加载 | 中：若免审批则等于开后门 | **已实现**；命令/监听必须人工批准，剧本入记忆不扩权 |
| 定时汇报 | ✅ asyncio 周期任务 + 规则汇总 | 低 | **已实现**；LLM 摘要可选（计费），默认关 |
| QQ 通道 | ✅ OneBot v11 HTTP 适配器 | 中：远程入口 + 协议合规 | **已实现**；白名单用户/群 + webhook token，审批不放宽 |
| 代码学习与脚手架 | ✅ 扫描/风格画像/沙箱生成 | 中：不可承诺自动产出可用项目 | **已实现（受限）**：只读 scan_dirs、只写 workspace_dir、写入需审批、不执行代码 |

**审批模型**：工具执行分三级 —— `free`（只读查询，直接执行）/ `confirm`（会改变系统状态，
推送审批卡片，用户点"批准"才执行）/ `deny`（配置中未列入白名单，一律拒绝）。
能力进化复用同一模型：只扩"命令 / 监听 / 剧本"三类声明式能力，**不能加载任意代码**，
批准后写 `data/config.runtime.yaml` 并热加载，同时留下审计记忆。

### 2.3 跨平台部署

| 项 | Windows | Linux |
|----|---------|-------|
| 运行 | `python -m agentd` 或 nssm 注册为服务 | `python3 -m agentd`，配 systemd unit |
| 日志路径 | `D:\app\logs\xxx.log` | `/var/log/app/xxx.log` |
| 进程管理 | taskkill / 命令白名单 | kill / systemctl，白名单同理 |
| 差异处理 | 全部封装在 `system.py` / `tools.py` 的平台分支里，上层逻辑无感 |

**结论**：基础功能（状态感知、日志监听、告警上报、LLM 分析）全部成熟可行；
"给解决方案"定位为辅助建议而非保证；控制电脑第一版限定在白名单+审批，
既安全又足以覆盖"启停项目、执行运维命令"的真实场景。

## 3. 关键设计决策

1. **双层日志检测**：规则层（毫秒级、免费）负责"及时上报"，LLM 层负责"分析与方案"。
   告警触发时自动把错误上下文注入对话上下文，用户打开控制台即可追问"怎么修"。
2. **LLM Provider 抽象**：`openai_compatible`（OpenAI/DeepSeek/通义/MiMo 等一切兼容
   `/v1/chat/completions` 的服务）与 `ollama`（本地 `/api/chat`）两个实现，配置切换。
3. **无构建前端**：原生 HTML/CSS/JS + 手写 canvas 图表，零依赖零 CDN，
   离线可用，Windows/Linux 打开即用。
4. **单进程异步**：FastAPI + asyncio；日志监听用后台线程（阻塞读）通过线程安全队列
   回灌事件循环，避免 GIL/阻塞问题。
5. **状态推送**：WebSocket 单连接双向复用——服务端每 2s 推系统指标、
   实时推日志行与告警；对话也走 WS，审批结果经 WS 恢复 Agent 循环。

```
agent/
├── README.md              # 部署与使用说明
├── docs/DESIGN.md         # 本文档

│   ├── memory.py          # 长期记忆（自我学习）
│   ├── capabilities.py    # 能力进化（自我进化）
│   ├── llm.py             # LLM Provider (T5)
│   ├── tools.py           # 工具注册 + 白名单 + 审批 (T6)
│   ├── agent.py           # Agent 工具循环 + 记忆注入 (T5)
│   └── server.py          # FastAPI 服务 (T7)

    ├── index.html
    ├── style.css
